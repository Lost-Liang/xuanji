# Agent 角色边界修复总结

**日期**: 2026-09-11  
**修改文件**: `packages/core/src/graph/agent-node.mts`  
**提交**: `1f9c776`

---

## 问题背景

从任务 `728fbb58-bd42-4492-9424-38500eaa4532` 的执行日志分析中发现严重的 Agent 角色越界问题：

1. **write_tests** 没有验证测试是否可运行
2. **develop** 修复了测试代码（应该只修复业务代码）
3. **test** 花费 17 分钟修复代码（应该只运行测试并报告）
4. 所有 Agent 都倾向于自己修复问题，而不是回退给上游

**根因**: Agent Prompt 中没有明确的职责边界和禁止行为约束

---

## 解决方案

为所有 5 个 Agent 添加了完整的角色定义：

### 1. write_tests (测试工程师)

**✅ 职责**:
- 根据验收标准编写测试代码
- 验证测试文件存在且可编译
- 输出测试文件列表和测试数量

**❌ 禁止**:
- 不要运行测试（环境可能不支持）
- 不要修复业务代码
- 不要修改已有的测试代码
- 不要解决环境问题

**验证要求**:
- 测试文件确实已创建
- 测试代码可以编译
- 测试数量与输出一致

---

### 2. develop (全栈开发工程师)

**✅ 职责**:
- 实现业务逻辑，让测试通过
- 创建必要的业务代码文件
- 验证代码可以编译

**❌ 禁止**:
- 不要修改测试代码（那是 write_tests 的职责）
- 不要运行测试（那是 test 的职责）
- 不要修复测试基础设施
- 不要解决测试配置问题

**验证要求**:
- 业务代码确实已创建/修改
- 代码可以编译
- 没有修改任何测试文件

---

### 3. test (测试验证员) ⭐ 关键修复

**✅ 职责**:
- 运行测试并报告结果
- 报告测试失败的具体情况（文件、行号、错误信息）
- 验证编译是否通过

**❌ 禁止**:
- **不要修复失败的测试**（那是 write_tests 的职责）
- **不要修复业务代码**（那是 develop 的职责）
- **不要修改任何代码文件**
- **不要调试问题**（发现问题就报告，让上游处理）

**回退规则** ⭐:
如果测试失败，你必须：
1. **停止执行**
2. **报告失败的测试详情**
3. **在 JSON 输出中设置 ok=false**
4. **不要尝试自己修复问题**

**验证要求**:
- 测试确实运行了（不是跳过或编译失败）
- 测试结果与实际运行一致
- 没有修改任何代码文件

---

### 4. code_review (代码审查员)

**✅ 职责**:
- 审查代码质量（代码规范、设计模式、潜在问题）
- 报告发现的问题（严重程度、具体位置、改进建议）
- 给出审查结论（通过或驳回）

**❌ 禁止**:
- **不要修复发现的问题**（那是 code_fix 的职责）
- **不要修改任何代码文件**
- 不要运行测试（那是 test 的职责）
- 不要实现新功能

**回退规则**:
如果发现问题，你必须：
1. 详细列出所有问题（文件、行号、问题描述、严重程度）
2. 在 JSON 输出中设置 approved=false
3. 不要尝试自己修复问题

**验证要求**:
- 审查基于实际代码（不是假设）
- 问题描述具体可定位
- 没有修改任何代码文件

---

### 5. code_fix (代码修复工程师)

**✅ 职责**:
- 修复 code_review 发现的问题
- 验证修复后的代码可以编译
- 报告修复的文件和解决的问题

**❌ 禁止**:
- 不要修复审查中未提到的问题
- 不要添加新功能
- 不要修改测试代码（那是 write_tests 的职责）
- 不要做超出审查范围的重构

**验证要求**:
- 修复确实已完成（检查文件是否修改）
- 代码可以编译（运行编译命令）
- 只修复了审查中提到的问题
- 没有引入新的问题

## 预期效果

### 修复前 vs 修复后

| Agent | 修复前 | 修复后 |
|-------|--------|--------|
| **write_tests** | 写测试但不验证 | 写测试并验证可编译 |
| **develop** | 实现功能 + 修复测试 | 只实现功能 |
| **test** | 运行测试 + 修复代码（17分钟） | 只运行测试并报告 |
| **code_review** | 未执行 | 审查但不修复 |
| **code_fix** | 未执行 | 只修复审查中的问题 |

### 关键改进

1. **角色边界清晰**: 每个 Agent 明确知道什么能做、什么不能做
2. **回退机制强制**: test 和 code_review 发现问题时必须停止并报告，不能自己修复
3. **验证要求明确**: 每个 Agent 必须验证自己的交付物真实有效
4. **职责不重叠**: 消除了多个 Agent 做同一件事的情况
