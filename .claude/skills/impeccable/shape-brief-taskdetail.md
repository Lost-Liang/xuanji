# TaskDetail 设计简报

## 1. Feature Summary

任务详情页是控制台中信息密度最高、功能最丰富的页面。用户需要在一个页面中完成三件事：
1. **快速了解执行状态**：当前在哪个阶段、是否正常、执行了多久
2. **审查产出物**：查看代码变更、测试结果、日志细节
3. **人机协作决策**：通过对话干预执行、在 Review Gate 做决策

目标用户是混合群体：技术背景的研发需要深入细节，非技术背景的产品经理需要快速了解进度。

## 2. Primary User Action

**一眼看清状态，按需深入细节。**

用户来到页面时，最先看到状态概览和执行进度。如果一切正常，可能只是确认一下就走；如果需要干预或审查，则展开相应的折叠区域。

## 3. Design Direction

**Color Strategy**: Restrained（克制）
- 深色终端底色为主
- 状态色（青/绿/红/黄）用于传达执行状态，占比不超过 15%
- 不使用渐变、发光等装饰效果

**Theme Scene Sentence**:
> 研发工程师在下午 3 点的办公室里，盯着屏幕监控一个已运行 20 分钟的任务，需要快速确认当前进度，并在出现异常时介入处理。

→ 深色主题，信息密度高，关键状态突出。

**Anchor References**:
- **Linear**: 信息密度高但层次分明，卡片边界克制
- **Vercel Dashboard**: 状态优先的设计，一眼看清部署进度
- **GitHub Actions**: 阶段卡片流的交互模式，每个阶段可展开查看详情

## 4. Scope

- **Fidelity**: Production-ready
- **Breadth**: 单页面（任务详情页）
- **Interactivity**: 完整交互（折叠/展开、抽屉、按钮状态）
- **Time Intent**: Polish until it ships

## 5. Layout Strategy

**单列布局，顶部双卡并列**：

```
┌─────────────────────────────────────────────────────────┐
│ Breadcrumb: 任务 / task-id                              │
├─────────────────────────────────────────────────────────┤
│ ┌─ 状态概览 ─────────┐  ┌─ 执行进度 ─────────────────┐ │
│ │ (左卡片)           │  │ (右卡片)                   │ │
│ │ 状态、标题、元信息  │  │ 阶段卡片流                 │ │
│ │ 操作按钮、Session   │  │ [拆分][编码][测试]...     │ │
│ └────────────────────┘  └────────────────────────────┘ │
├─────────────────────────────────────────────────────────┤
│ ┌─ Phase 产出物 ─(默认折叠)──────────────────────────┐ │
│ │ 展开后显示每个 phase 的文件变更、Diff、测试结果     │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
│ ┌─ 拆分内容 ─(默认折叠)──────────────────────────────┐ │
│ │ 任务类型、验收标准、优先级等结构化信息              │ │
│ └─────────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────────┤
│ 实时事件流 → 右侧抽屉，点击按钮打开                    │
│ Session Refs → 集成在状态概览卡片中                   │
└─────────────────────────────────────────────────────────┘
```

**视觉层次**：
1. 第一眼：状态标签 + 进度卡片（最亮的信息）
2. 第二眼：标题、当前节点、时间
3. 按需展开：产出物、拆分内容、实时日志

## 6. Key States

| 状态 | 用户需要看到 | 视觉处理 |
|------|-------------|---------|
| **默认（加载完成）** | 状态概览 + 进度并列 | 两个卡片左右排列 |
| **执行中** | 进度高亮当前阶段，运行态动画 | 青色边框发光 |
| **限流中** | 显示退避倒计时 | 黄色警告色 |
| **暂停中** | 显示"等待人工决策"或"已暂停" | 黄色 |
| **失败** | 显示失败原因，重试按钮 | 红色 |
| **已完成** | 显示完成时间、总用时 | 绿色 |
| **Review Gate** | 显示批准/驳回操作区 | 黄色高亮 |
| **空状态** | 无产出物时的引导 | 灰色占位 |

## 7. Interaction Model

**页面级交互**：
- 进入页面：加载任务详情，默认展开状态和进度
- 实时刷新：执行中/限流中状态时，每 5 秒刷新数据

**卡片交互**：
- 折叠/展开：点击卡片标题栏折叠/展开
- Phase 产出物：每个 phase 独立折叠，点击展开查看详情

**操作按钮**：
- 查看画布：跳转到 `/canvas?execution_id=...`
- 对话：打开右侧抽屉的对话面板
- 日志：打开右侧抽屉的日志面板
- 暂停/取消/继续/重试：API 操作 + 刷新数据

**抽屉交互**：
- 右侧抽屉可切换 Tab：日志 / 对话
- 抽屉宽度 480px，可拖拽调整

## 8. Content Requirements

**状态概览卡片**：
- 状态标签（带图标）：执行中/已完成/失败/限流中/暂停
- 任务标题（从 breakdown_content 提取）
- 任务 ID（短版）
- 当前节点
- 开始时间 / 用时
- Token 消耗（输入/输出）
- 成本
- 主 Session 入口（对话按钮）
- 操作按钮组

**执行进度卡片**：
- 阶段卡片流：每个阶段一个小卡片
- 卡片内容：阶段名称 + 状态图标
- 当前阶段高亮
- 完成阶段显示对勾
- 失败阶段显示叉号

**Phase 产出物**：
- Phase 标题：节点名称 + iteration
- 文件变更列表：
  - 新增：绿色 `+` 前缀
  - 修改：黄色 `M` 前缀
  - 删除：红色 `-` 前缀
- Diff 内容：语法高亮（可选），可折叠
- 测试结果：通过/失败摘要
- PR 链接：可点击跳转

**空状态文案**：
- 无产出物："任务执行中，暂无产出物"
- 无拆分内容："暂无结构化拆分信息"
